# DX-024: Indexing cost risk

[Catalog](../detectors.md) | [Access and sign-in](../permissions.md)

## Data and scope

The all-container inventory pass evaluates NoSQL containers independently of throughput
offers, including dedicated, shared-database and serverless containers.
It reads the latest jointly measured `IndexUsage` and `DataUsage` samples in a six-hour window
at five-minute grain, scoped by database and collection. ARM supplies indexing mode and
excluded paths. No Log Analytics is required.

## Detection and severity

| Configuration | Default |
|---|---|
| `review_ratio` | `0.3` |

Divide index bytes by data bytes. A ratio strictly above 0.3 prompts an **ungraded review**.
Exactly 0.3 does not trigger a review; above 1.0 remains ungraded. There are no severity bands.
An explicit indexing mode of `none` on a verified resource is not detected, even if the
storage read fails. Unknown storage is not reported as a measured zero.

Missing, negative or non-finite sizes, or zero data size, are insufficient data. A real
zero index size with positive data is a valid zero ratio. User-authored exclusions do not
suppress a finding: their count is evidence. `/_etag/?` and `/"_etag"/?` are the two
default exclusions excluded from that count.

## Evidence and limits

CODA can collect index and data sizes for multiple named containers in one database-scoped
request. Each container retains its own indexing policy and observations. Ambiguous or incomplete
series can trigger bounded individual recovery; an unresolved unit is reported as incomplete,
not silently skipped or treated as healthy.

The grouped read and its retry must both establish the requested metric, container, byte unit,
time span, grain, and consecutive time slots. If the retry returns only an early index size
of 80 bytes against 100 bytes of data, that is *not* enough to report an 80% ratio. In
contrast, if the full grid ends in a measured 5 bytes followed by a null slot, 5 bytes is
the latest populated value. Independent groups can be read concurrently without changing
report order or the shared eight-read recovery limit.

With 100 GiB of data, 30 GiB of index does not trigger review. At 31, 100 or 101 GiB
the report shows both sizes and invites review of representative queries. A null bucket
is not zero. If no bucket contains both measurements CODA cannot report a ratio.

This is a storage-footprint warning, **not proof of unused indexed paths, query-scan
inefficiency, vector usage, or a measured write-RU saving**. Composite, spatial and vector
indexes may legitimately be large. Failed reads are errors.

Grouped and individual histories matched on named fixture containers. This verifies that
query shape on those fixtures, not latency on a large production account.

## Remediation and references

Use
[`index-exclude-unused`](https://github.com/AzureCosmosDB/cosmosdb-agent-kit/blob/main/skills/cosmosdb-best-practices/rules/index-exclude-unused.md)
to review actual filter/sort requirements before changing the indexing policy.
Do not exclude paths solely because the ratio is large. CODA does not change indexes.
