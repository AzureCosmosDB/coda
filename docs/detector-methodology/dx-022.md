# DX-022: Per-region autoscale opportunity

[Catalog](../detectors.md) | [Access and sign-in](../permissions.md)

## Data and scope

Account-level ARM review of throughput offers, serverless capability and the reported
per-region/per-partition autoscale flag (`is_pppra_enabled`). It uses current configuration,
not a workload window, and requires neither metrics nor Log Analytics for its predicate.

## Detection and severity

| Configuration | Result |
|---|---|
| Serverless | Not detected |
| Complete inventory without autoscale offers | Not detected |
| Per-region/per-partition autoscale already enabled | Not detected |
| At least one dedicated or shared autoscale offer, flag explicitly off | High-priority cost recommendation, in one or multiple regions |
| Missing flag with an autoscale offer, or incomplete inventory without a confirmed offer | Insufficient evidence |

The current registry labels the configuration predicate `validated`. That label is not
proof that a given account will benefit or that a fresh live acceptance has occurred.

## Evidence and limits

A single-region autoscale container with the flag off qualifies: physical partitions can
scale independently. Two regions with only manual offers do not qualify. Region count
is evidence, not a gate. No resource age or measured demand skew is required. A failed
read is not evidence that the feature is disabled. No recoverable RU/s or monetary
savings are calculated.

## Remediation and references

There is no mapped Agent Kit rule (`agent_kit_rule` is null). Recommend enabling
[dynamic autoscale](https://learn.microsoft.com/azure/cosmos-db/provision-throughput-autoscale#enabling-dynamic-scaling)
without downtime. This does not redesign a skewed logical key or remove its capacity limit.
CODA does not enable the feature.
