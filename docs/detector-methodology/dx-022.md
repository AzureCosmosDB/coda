# DX-022: Per-region autoscale opportunity

[Catalog](../detectors.md) | [Access and sign-in](../permissions.md)

## Data and scope

Account-level ARM review of region count, serverless capability and the reported
per-region/per-partition autoscale flag (`is_pppra_enabled`). It uses current configuration,
not a workload window, and requires neither metrics nor Log Analytics for its predicate.

## Detection and severity

| Configuration | Result |
|---|---|
| Serverless | Not detected |
| Fewer than two regions | Not detected |
| Per-region/per-partition autoscale already enabled | Not detected |
| At least two regions, not serverless, flag off | Low candidate |

The current registry labels the configuration predicate `validated`. That label is not
proof that a given account will benefit or that a fresh live acceptance has occurred.

## Evidence and limits

Two regions with the flag off meet the configuration predicate; one region does not.
The predicate **does not require an autoscale offer** and does not measure per-region
demand skew. A manual-only account can therefore receive this advisory.

Confirm the actual throughput mode, current feature state and regional/partition demand
before enabling anything. No recoverable RU/s or monetary savings are calculated.
A failed ARM read is an error, not evidence that the feature is disabled. A configuration
snapshot is not a complete feature eligibility assessment.

## Remediation and references

There is no mapped Agent Kit rule (`agent_kit_rule` is null). Evaluate the service's current
per-region/per-partition autoscale capability if the account uses autoscale and uneven demand
justifies it. This does not redesign a skewed logical key or remove its capacity limit.
CODA does not enable the feature.
