# DX-009: Partition merge candidate

[Catalog](../detectors.md) | [Access and sign-in](../permissions.md)

## Data and scope

Reviews physical-partition count for provisioned containers using `PhysicalPartitionCount`,
`DataUsage` and ARM throughput. This check always uses its recent six-hour window at
five-minute grain, including when other detectors use evaluation windows.
It reads maxima over that window, not a hypothetical post-merge workload.

## Detection and severity

Required partitions are the maximum of throughput divided by 10,000 RU/s (rounded up),
storage divided by 50 GiB (rounded up), and one. More actual partitions than required
produce a finding: Medium at at least twice the need, otherwise Low. There is no High band.

An actual count of one cannot be a merge candidate; no observed count is insufficient data.
For 20,000 RU/s and 10 GiB, two partitions are needed: three actual is Low, four is Medium.

## Evidence and limits

Structural excess is **not merge eligibility**. Backup policy, migration metadata and
optional all-versions-and-deletes enablement constrain the action without hiding the finding:

| Account evidence | Action boundary |
|---|---|
| Continuous backup, any PITR tier | Merge blocked; continuous backup cannot be reverted to periodic on this account |
| Missing/unrecognized policy or backup migration metadata | Eligibility unknown; withhold merge instructions |
| Full-fidelity change feed enabled with inconsistent backup metadata | Block guidance pending verification; enablement does not prove active consumption |
| Settled periodic backup | Require the Portal eligibility checker and current platform/SDK/connector restrictions |

Fabric Mirroring is not assessed; PITR is not proof of Mirroring use. Do not recommend
disabling protection/dependent features or migrating accounts to circumvent the blocker.

A failed metric call is an error. The current detector treats a **successful empty DataUsage
series as zero storage** when count exists; that is a limitation, not measured zero.
Verify storage and service restrictions before acting. Maxima may describe different moments,
and future growth or workload skew is not simulated.

## Remediation and references

`agent_kit_rule` is null: this is a platform operation, not a mapped code remedy.
CODA never merges partitions. Periodic backup alone is not permission or full eligibility.
