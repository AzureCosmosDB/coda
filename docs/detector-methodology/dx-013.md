# DX-013: Autoscale-to-manual candidate

[Catalog](../detectors.md) | [Access and sign-in](../permissions.md)

## Data and scope

For a dedicated autoscale offer, show the measured scaled RU/s relative to the configured
maximum. Sum hourly `AutoscaledRU` maxima across physical partitions only when their count
agrees with the offer's independent five-minute partition counts throughout that hour.
`NormalizedRUConsumption` is not actual autoscale provisioning.
Azure [documents `AutoscaledRU` for dynamic autoscale and `ProvisionedThroughput` for billed hourly throughput](https://learn.microsoft.com/azure/cosmos-db/provision-throughput-autoscale#monitoring-metrics).
When traditional autoscale is confirmed, use the historical `ProvisionedThroughput` maximum
for each region; ARM still supplies the configured maximum. No usable series means no
provisioning-based comparison, not zero scaled RU/s.

## Detection and severity

| Configuration | Default |
|---|---|
| `measured_review_hours` | `168` |
| `measured_advice_hours` | `720` |

Show measurements immediately. A favorable comparison in the **latest 168 completed hours**
prompts an ungraded review, not conversion advice. A **Medium**, proposal-threshold finding
requires the **latest 720 completed hours**, each fully measured, and a strictly lower
estimated throughput cost for manual. A gap yesterday blocks even the review; an older gap
can leave a complete recent week, but not a qualifying month. No steady-high or peak-to-average
test applies. An open hour does not replace a completed one.

In each measured hour, compare actual scaled throughput (subject to the 10% billing minimum)
with manual throughput **fixed at the same configured maximum**. For a paid single-write
account, autoscale uses 1.5 times the common meter quantity; manual uses 1.25 in an explicitly
zone-redundant region, otherwise 1. Multi-write uses the same regional per-unit rate for both
modes, with neither premium: manual cannot beat autoscale at equal capacity by avoiding a
nonexistent premium. The common price cancels **within each region**. An equal
estimate is not a reason to switch. No reduced target, recoverable RU/s or dollars are quoted.

## Evidence and limits

Example: a 10,000 RU/s offer alternates between 4,000 and 10,000 scaled RU/s every hour in a
non-zone-redundant region. In each pair of hours autoscale uses (40 + 100) × 1.5 = 210 meter
units; manual at **10,000 RU/s throughout** uses 200. This **variable** pattern can favor
manual after the full month. In a zone-redundant region manual instead uses 250 units for
the same two hours. A favorable result after only a week asks whether the week is representative.

In multiple regions, compare actual hourly provisioning **separately** for all configured
regions over the same recent week/month. Do not copy a global or West-only series into East.
If West uses 90% but East uses 10%, single-write manual can beat autoscale in West yet cost
more in East. Opposite regional estimates need separate regional unit prices; an account-wide
blended rate does not settle them. Confirmed non-increasing cost in every region and a strict
decrease in at least one is sufficient without those prices. Missing regional evidence,
unverified multi-region scaling or zone settings, free tier or unsupported capacity also
withhold advice. Confirm the
maximum and billing configuration held throughout the measured period. Reservations, future
traffic and commercial terms affect the bill; the estimate does not promise future savings.
