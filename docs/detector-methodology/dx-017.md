# DX-017: Container storage growth

[Catalog](../detectors.md) | [Access and sign-in](../permissions.md)

## Data and scope

For a provisioned container with its own throughput offer, read Azure Monitor `DataUsage`
(bytes, Maximum) at hourly grain, scoped by database and collection, over 30 days. This
measures container data storage, not a single physical partition, logical key, or index size.
There is no age floor. No Log Analytics is needed.

## Detection and severity

| Configuration | Default |
|---|---|
| `consecutive_growth_days` | `3` |

Show the first and last measured sizes, timestamps and net change. A single size is an
observation with unknown change. A missing size is not zero. All results are ungraded.

For retention or archival review, require three consecutive fully measured UTC days:
all 24 completed hourly values must be present on each day, and the final hourly value
must exceed the first on **each** day. Days separated by gaps or a flat day cannot be joined.
The hourly values are maxima in their respective buckets, not continuous measurements.

## Evidence and limits

An import takes storage from 40 to 90 GiB on Monday; Tuesday and Wednesday are flat.
Report +50 GiB, not a growth rate or deadline. If Monday, Tuesday and Wednesday instead
end at 42, 44 and 46 GiB after beginning at 40, 42 and 44 GiB respectively, with all
72 hourly measurements, review retention or archival needs with the data owner.

## Remediation and references

50 GiB is not a container limit. Do not prescribe TTL, deletion or a new partition key.
Logical-key size is a separate [DX-015 check](dx-015.md).
