# DX-002: Cross-partition query fan-out

[Catalog](../detectors.md) | [Log prerequisites](../detections/log-analytics-readiness.md)

## Data and scope

Evaluates containers, including the serverless pass. Production requests one day of
`CDBQueryRuntimeStatistics` and raw `CDBDataPlaneRequests` through account-resource queries.
The five-minute request aggregate is not a substitute for this raw request-charge join.
Unavailable prerequisites, insufficient records and failed queries must remain distinguishable.

Logical queries are grouped by correlated activity and query text. Distinct partition ranges
measure fan-out; request charge joins on activity ID provide RU evidence. The query keeps the
200 most frequent shapes. The widest observed fan-out estimates partition count; it is not
an authoritative inventory of every physical partition.

## Detection and severity

| Configuration | Default |
|---|---|
| `min_queries` | `50` |
| `cross_fanout_threshold` | `1.5` |
| `min_share_pct` | `10.0` |
| `min_rate_qps` | `0.1` |
| `high_rate_qps` | `1.0` |
| `medium_partitions` | `4` |
| `high_partitions` | `7` |

A shape averaging at least 1.5 partitions counts as cross-partition. At least 50 observed
executions, more than one observed partition, at least 10% cross-partition executions and
at least 0.1 fan-out executions per second are needed. The rate uses the actual window
duration. Below the rate floor is occasional fan-out, not a finding. **RU is not a gate.**

| Observed partitions | Rate below 1 query/s | Rate at least 1 query/s |
|---|---|---|
| 2-3 | Low | Low |
| 4-6 | Low | Medium |
| 7+ | Medium | High |

## Evidence and limits

In a one-hour window, 359 fan-out executions are below the rate floor; 360 reach it.
Across seven observed partitions, 3,599/hour is Medium and 3,600/hour is High.
Use unrounded values for decisions: displayed percentages/rates can round onto a boundary.

Query text can be anonymized or contain sensitive text depending on logging; never assume
it is safe to send to another model. A shape is not proof of the original source-code query
or the correct partition key. Legitimate analytical fan-out can still meet these gates.
No/fewer-than-50 executions abstain. A reported query failure is not a clean result, even
where the detector's legacy reason token is `log_analytics_unavailable`.
